# MikroORM Notes

The CLI is configured with `tsimp` explicitly in `package.json`. MikroORM checks
for TypeScript loaders in a fixed order and can otherwise select `jiti` from a
transitive workspace dependency. In this project, the automatically selected
loader failed to transform definite-assignment entity fields such as
`title!: string`. After removing those assertions experimentally, it loaded
related entity modules under different runtime identities and MikroORM reported
duplicate table metadata. Selecting `tsimp` keeps TypeScript entity loading
deterministic. Run MikroORM CLI commands from this app directory or through a
root `pnpm --filter skolark-portal-api ...` script because the CLI dependency is
app-local.

Legacy entity decorators use `ReflectMetadataProvider`, configured in
`src/config/mikro-orm.ts`. Without it, MikroORM 7 uses its base metadata
provider, which requires an explicit `type` or `entity` on every property even
though `emitDecoratorMetadata` is enabled. With reflection enabled, ordinary
TypeScript scalars can omit redundant database types:

```ts
@Property()
title!: string;

@Property({ nullable: true })
publishedAt?: Date;
```

Keep an explicit type when it expresses storage semantics that TypeScript
cannot infer, including `uuid`, `text`, and `json`. Nullable columns are modeled
as optional properties (`property?: Type`) rather than `Type | null` with a
`null` default. Required ORM-hydrated fields retain the definite-assignment
assertion (`property!: Type`).

Entity IDs are optional before persistence and generated by PostgreSQL:

```ts
@PrimaryKey({ defaultRaw: 'gen_random_uuid()', type: 'uuid' })
id?: string;
```

The local connection URL must match `.docker/postgres.env`. The current local
database uses the `admin` user and the `skolark-portal-api` database. If the CLI
reports PostgreSQL error `28P01`, check `MIKRO_ORM_DATABASE_URL` in `.env.local`
or `.env`; that error occurs after entity transformation and metadata discovery
have already succeeded.
